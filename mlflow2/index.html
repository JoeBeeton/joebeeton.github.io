A regression of CVE-2023-43472. This page is the attacker site: everything below is triggered by a page you merely visit, against an MLflow server running on your own machine.

Each demo fires a cross-site request at a local MLflow server and then shows the proof it leaves behind. Cross-site responses are blind to this page, so the proof is read from a same-origin /results/ oracle (for the blind attacks) or directly from the server where the wildcard-CORS config makes it readable.

Live attacks

Other confirmed findings (not wired as live buttons here)

  • F3 — Assistant health GET side-effect (Low–Med). A cross-site GET …/assistant/providers/claude_code/health launches the agent CLI, which starts the project's configured MCP servers — no prompt, no approval.
  • F8 — Prompt-optimization job cancel (Low). Path-param-only POST, no body gate; cancels any job given a leaked job id.
  • F11 — Job-API scorer trust boundary (Med). submit_job skips the scorer-payload validation the registration route applies, so a caller can redirect the judge's LLM calls (carrying the server credential) and impersonate any user to the gateway.
  • F12 — GenAI agent server (High). Separate server: cross-site text/plain POST runs the developer's agent with attacker input; default bind 0.0.0.0.
  • F13 / F14 — Standalone gateway & scoring server (Med / Low–Med). No Host validation → reachable via DNS rebinding (not a simple-request drive-by).
  • F15 — basic-auth does not help. Browsers attach cached HTTP Basic credentials to cross-site simple requests, so F1/F2 work against a logged-in user too.
Mock mode (default) uses an in-stack mock provider and a stub agent — no real calls, no secrets. To verify for real on your own machine, put a key in .env (see .env.example); the banner turns red.
